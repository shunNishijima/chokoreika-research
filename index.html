サービス設計（受付アプリ）

朝ご飯会・映画会などの受付で、出欠と参加者の基本情報・今の気持ちを記録し、地域ごとの活性度や気持ちの変化をダッシュボードで見せる。iPad で運営のシニアが操作する前提で作っている。

2026-11-22 時点の実装に基づく。【試用】は試用モードの間だけの仕様。

1. システム構成

要素使っているもの役割
画面React・Vite・Tailwind CSS、地図は d3-geo（SVG）受付（/kiosk・/neko）と管理画面（/admin）
APIHono（Node.js）、入力検証は zod受付・管理・集計・CSV・デモデータ
DBCloud SQL（PostgreSQL 16）、ORM は Drizzle参加者・会・出席・選択肢・設定。起動時にマイグレーション

デプロイGitHub Actions（Workload Identity 連携、鍵なし）main に push → テスト → 変更があったサービスだけ自動デプロイ

はじめての方

  • 記録の同意（いいえ → 何も保存せず完了）
  • 名前
  • 老人会（入っていない も可）
  • お住まいの市町村

4. データ設計

表主な項目メモ
participants（参加者）ID（4桁の連番）、同意、名前、年代、生まれ年、性別、市町村、老人会、きっかけ、一人暮らし、来た手段同意がない人は ID と同意だけ保存。住所・電話番号は持たない

5. ダッシュボードの指標

指標計算
参加した人数／延べ参加回数期間中に1回以上来た人数／出席の合計
はじめて来た人全期間で最初の出席が期間内の人
リピート率2回以上来た人 ÷ 参加した人数
担い手準備・担当を1回以上した人
非会員・一人暮らし・杖や手押し車同意した人（または回答した人）の中での割合
気持ちの変化来たとき・帰るときの両方に答えた出席だけで、平均の差と良くなった／同じ／下がった人数
地域ごとの活性度市町村ごと（と市町村×月）の延べ参加回数・参加した人数・はじめて・1人あたり回数・担い手

6. 試用モードと個人情報

  • 【試用】ログインなし（ADMIN_AUTH=none）。受付の合言葉も不要。URL を知っている人は誰でも管理画面を見られるため、URL は運営の中だけで共有する
  • 全ページに検索エンジンに載せない設定（noindex）
  • 名前は管理画面の画面だけに表示し、CSV と外部共有モードには出さない
  • 本番では認証を戻す（Google ログインと許可リスト、または合言葉。実装済みで設定を切り替えるだけ）

7. デモデータ

管理画面の「設定」から投入・削除できる架空のデータ（過去6か月・約90人・大阪府内の市町村）。会場が「（デモデータ）」、名前が「デモ 」で始まる。削除するとデモだけが消え、本物の記録は残る。

8. 決めていないこと

  • 本番運用での認証方式（Google ログイン／合言葉）
  • 標準の受付とネコ受付のどちらを使うか、または両方か
  • 年代と生まれ年のどちらで記録するか（今は受付ごとに違う）
  • 企業・行政に見せる指標（ヒアリングで決める）
  • ekyam_japan（SCダッシュボード）への統合の仕方

受付アプリの使い方

朝ご飯会の受付アプリ（試用版）の画面の流れと、どこで何を入力・確認できるかのまとめ。iPad で受付し、記録は管理画面のダッシュボードで見る。

試用モード ログインなしで使える。URL を知っている人は誰でも管理画面（名前など）を見られるので、URL は運営の中だけで共有する。画面の写真は架空のサンプルデータ。

URL

使う場面URL使う人
受付（iPad）checkin/（このサイト内の入口。https://choko-checkin-r4inbionxq-an.a.run.app/kiosk に移動）運営のシニア・参加者
管理画面https://choko-checkin-r4inbionxq-an.a.run.app/admin運営（学生インターン など）

iPad では Safari で受付の URL を開き、共有ボタン →「ホーム画面に追加」にすると、アプリのように全画面で使える。

全体の流れ

① 運営が会を始める
老人会 → 会の種類 → 次回の日付② ようこそ
今の気持ち③ 受付
はじめての方 / 2回目からの方④ 退出
帰るときの気持ち⑤ 管理画面で見る
ダッシュボード・開催・参加者

① 運営が会を始める（受付の最初）

iPad で受付を開くと、まず運営の人が3つ入れる。同じ日・同じ老人会・同じ種類なら、新しく作らずに同じ会を開く（iPad を2台使っても同じ会にまとまる）。

② ようこそ・今の気持ち

ようこその画面が受付の待ち受けになる。参加者が画面を押すと、今の気持ちを5つの表情から選ぶ（来たときの気持ちとして記録）。右上の「読み上げ」をオンにすると質問を声で読む。左下は退出、右下は運営用の「会を選び直す」。

③ 受付：はじめての方

1画面に1問。答えると自動で次へ進み、「戻る」はいつでも押せる。質問は順に、記録の同意 → 名前 → 老人会 → 市町村 → きっかけ → 年代 → 性別 → 一人暮らし → 来た手段（最後の2つは「とばす」可）。同意しない人は名前も含めて何も保存しない。最後に ID（4桁）と参加カード（QR・次回の日付）が出る。

③ 受付：2回目からの方

ID を数字のボタンで押す（参加カードの QR をカメラで読むこともできる）→「おかえりなさい、○○さん！」。同じ会で2回受付しても二重には記録されない。

④ 退出

ようこその画面の「お帰りの方（退出）」→ ID → 帰るときの気持ち → 次回の日付を表示。来たときと帰るときの気持ちの変化がダッシュボードに出る。完了画面は12〜15秒で自動でようこその画面に戻る。

⑤ 管理画面

タブできること
ダッシュボード期間（全期間・3か月・6か月・1年）と会の種類で絞り込み。主要な数字（参加した人数・はじめて来た人・リピート率・担い手・非会員・一人暮らし・杖や手押し車など）、開催ごとの新規/リピート、気持ちの変化、地域ごとの活性度（大阪府の地図と市町村×月の表。延べ参加回数・人数・はじめて・1人あたり回数・担い手を切り替え。地図は「参加のある市町村に寄せる / 大阪府全体」を切り替え、市町村を押すと人数と人口が出る）。「設定」の「デモデータを入れる」で、架空のデータで見え方を確かめられる、属性の内訳。「外部共有モード」で5人未満の値を隠し、「印刷・PDF」で企業や行政への資料にできる
開催会の一覧と出席者（ID・名前・気持ち・退出時刻）。出席者の役割を「参加 / 準備を手伝った / 担当」に変える（担い手の数に反映）、間違えた出席の取り消し。日付を指定して会を作ることもできる
参加者登録した人の一覧（名前・属性）。参加者・出席・開催の CSV ダウンロード（CSV には名前を含めない）
設定受付で選ぶ「市町村」と「老人会」の一覧（1行に1つ。並び順＝受付の表示順）。「大阪府の市町村を読み込む」で地図と同じ43市町村が入る（名前をそろえると地図に色が付く）。老人会は受付で新しく入力した名前も自動で加わる。「受付の合言葉」は試用モードでは使わない

運営の段取り（例）

  1. 事前に管理画面の「設定」で町名と老人会を登録する（老人会は当日入力してもよい）
  2. 当日、iPad で受付を開き、老人会 → 会の種類 → 次回の日付 を入れる
  3. ようこその画面のまま入口に置く。迷う人には担当が代わりに押す
  4. 帰りに「お帰りの方（退出）」で ID と気持ちを入れてもらう
  5. 会のあと、管理画面の「開催」で準備・担当をした人の役割を付ける

絞り込んだ1つのプロダクト。 老人会のシニアと大学生が一緒に朝ご飯を食べる会。学生インターンが運営する。コミュニティの作り方は Drishtee のノウハウ を下敷きにする。

設計の原則（運営者の振り返りから）

お膳立てより出番

  • 運営が全部を整えない。できないこと・足りないものを残し、得意な人に任せる
  • 「しゃーないなぁ」と手伝ってもらえる頼み方をする

学校っぽくしない

  • 全員参加・時間割・出欠のような空気を避ける
  • 気持ちが沈みがちな人でも、ふらっと来て、ふらっと帰れる

来る必要性を作る

  • 「行けば助かる」理由があると来やすい
  • 支援の場とは打ち出さない（調査とも一致）

成功の判定

定量

  • 口コミで、こちらが誘っていない人が来た
  • Retention Rate（また来る人の割合）

定性

  • 「次はいつやるの？」と聞かれる（これまでのご飯会で、すでに聞かれるようになっている）
  • いなくなった人が戻ってくる（カムバック）

担い手化

  • 3か月で「やりたい」と手が上がるか（映画会では、みゆき会に「映画会担当」ができ、協力者も増えた）
  • 熱狂的なファン（担い手）3%
  • 運営ではなく、コアユーザーがユーザーを獲得してくる仕組み

集め方: 両者に同じ質問をする

同じ質問にすると、答えを横に並べて比べられる。答えは要約せず、本人の言葉のまま1枚に1文で書き出す。

  1. 最近うれしかったことは何ですか。
  2. 誰かの役に立てたと感じたのはどんなときですか。
  3. 人に教えられること、得意なことは何ですか。
  4. これからやってみたいことは何ですか。
  5. 普段の朝はどう過ごしていますか。
  6. どんな誘われ方なら、行ってみようと思いますか。

記録は「発言（そのまま）/ 学生かシニアか / 年代 / 日付」。氏名は書かない。

Drishtee のノウハウ

超幸齢化プロジェクトは、インドの Drishtee Foundation の日本支部として始まったプロジェクト。Drishtee のコミュニティ形成のノウハウを朝ご飯会で活かす。

Drishtee とは

  • 2003年設立。インドの農村で、持続可能性と共有された豊かさを育てることを掲げる（公式サイト）。
  • 農村と都市を価値の連鎖（バリューチェーン）でつなぎ、農村女性の小さな事業づくりに力を入れる。
  • フランチャイズ型で、村の起業家が地域に必要なサービスを届ける。
  • 掲げている考え方: 「個人主義ではなくコミュニティを築く」「住民自身が開発を担えるよう自治を強める」（Our Impact ページ）。

サービス概要

シニアに社会参加のきっかけと他世代交流の機会を届ける → 健康寿命の延伸と社会保障費の軽減

受益者

シニア（65歳以上）。特に、ご飯を1人で食べている人、足腰が悪く外出しにくい人、孤独な人。

負担者

企業・自治体の協賛（想定）。TBD 現時点で企業協賛は取れていない。

運営者

学生（豊中の学生運営NPO）。

対象人口のメモ「200万人→3000万人」要確認 何の人数か（全国の65歳以上か、対象層か）と出典を確認してから使う。

価値定義

  • 社会保障費・介護費: 小規模NPOが「○円削減」を自前で示すことはできない。示せるのは参加者の孤独感・外出・共食の変化まで。その先は既存研究で説明する（例: 武豊町の住民主体サロンで要介護発生ハザード比 0.49）。
  • 社会的処方: 医療・福祉の窓口が孤立した人を地域活動に「紹介」する仕組み。豊中では社協CSW・校区福祉委員会・地域包括支援センターが紹介元になりうる。
  • 老人会にとっての価値: 持続可能な運営（業務負担の軽減・新規会員）。

どの小学校区にも、歩いて行ける距離に「多世代で食べて、観て、話す場」がある。孤立した高齢者は医療・福祉の窓口から紹介されてそこにつながり、元気な高齢者は迎える側に回っている。
この事業が果たし続ける使命は何か？
シニアに社会参加のきっかけと他世代交流の機会を届け続けること。担い手が入れ替わっても回る型と、効果を示すデータを地域に残すこと。
この価値を最大限続けた先には何がある？
社会的処方の受け皿として自治体の制度に組み込まれ、豊中の型が他の地域・海外に移植される（世界展開）。

課題特定（3つ）

草案

1. 払う人がいない

  • 企業協賛が取れない
  • 企業・市にとってのメリットを言語化できていない
  • 単一の財源に頼ると続かない（The Cares Family は2023年に閉鎖）

  • 学生を集められない（運営者に返るものがない）

  • 来るのは元気な老人会員が中心
  • 出席・属性・入会のデータがなく、効果もメリットも示せない

戦略策定（3つだけやるなら）

草案 課題1〜3に対応させています。

結論: 1つのプロダクト「朝ご飯会」に絞る。 大学生・老人会・学生インターンで、朝ご飯会だけを磨く。
以下の3つの戦略は、すべて朝ご飯会に当てはめて進める。開催頻度・場所・参加費は TBD。

論点 以前は断られた老人会から「映画会をやってほしい」という話が出ている。朝ご飯会に絞る方針と、映画会への需要をどう両立させるか（映画会はみゆき会の「映画会担当」など老人会側に任せる、など）を決める。

1. 記録を仕組みにする

  • 朝ご飯会の受付で出席・属性・会員/非会員を入力し、ダッシュボードで可視化する（ダッシュボード）
  • 老人会の事務負担を減らし、そのまま引き継ぎ資料にする
  • 1年目は基準値を取る実験と位置づける

2. 型を固定し、シニアを担い手に回す

  • 朝ご飯会を「同じ曜日・場所・流れ」で開き、手順をマニュアル化（引き継ぎ資料を兼ねる）
  • シニアに当番・語り手を任せ、学生が替わっても回るようにする
  • 学生には活動証明を返す
  • CSW・校区福祉委員から孤立層を紹介してもらう経路を作る

3. お金を三層に分ける

  • 変動費（食材・上映）は参加費（市内相場は1回300円程度）
  • 会場・保険は補助金（老人会が代表者になる形）
  • 企画・運営・測定は助成金（内閣府モデル調査、ニッセイ財団、コープ共済など）
  • 企業協賛はデータが溜まってから。メリット仮説（社員ボランティア・学生接点・シニアの声）をヒアリングで検証する

6. 守ること（非機能要件）

  • 個人情報: 氏名・住所を取らない。地域は町名まで。外部に見せるのは集計値だけ。町名は校区より細かく、1つの町の人数が少なくなりやすいので、個人が分かってしまうマス（例: 5人未満）は地図やグラフに出さない
  • 同意: 初回に、何のために記録するかを伝えて同意を取る（文面は TBD）
  • 使いやすさ: シニアが手伝いなしで受付を終えられる
  • 引き継ぎ: 管理者のアカウントを個人ではなく団体で持ち、運営者が替わっても使い続けられる
  • 費用: TBD（上限を決める）
